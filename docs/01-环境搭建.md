# 01 · 环境搭建

> 目标：把「本地出图 + 本地出视频」的地基铺好，并且让它们**不互相打架**。

---

## 1. 三件套

| 组件 | 作用 | 备注 |
| --- | --- | --- |
| **ComfyUI** | 出图 / 出视频的工作流引擎 | 装官方发行版即可，不赘述 |

## 2. 显存：先认清你的边界

我这张卡是 **12 GB 显存**。够用，但要有边界感：

- **出图阶段**：`1536×864` 直接出 + hires 二采到 `2304×1296`，一张稳定在 **40–60 秒**，显存吃得下。
- **出视频阶段**：视频模型比出图更吃显存，**必须单独跑**——不要在出视频的同时还开着出图任务。
- 结论一句话：**图、视频两条线串行，不要并发**。

### ⚠️ 分时复用（很重要）

本地同时装了「出图/视频的 ComfyUI」和「本地大语言模型」时，它们会**抢同一块显存**。

- 日常轻量能共存；
- 但**长任务（比如生成长段视频、或让大模型读 >1 万 token）前，先把另一个进程关掉**；
- 关键坑：`POST /free` **不够**——它只释放一部分，**CUDA context 要等进程真的退出才释放**。所以要「切引擎」时是**结束进程**，不是点一下 free；
- 启动参数别乱动：某些「省显存」参数在新版动态显存管理下是空操作、甚至**反而掉速**，别为了「看起来更省」而加。

> 判据：判断显存够不够，不要凭「大概率」，跑一次看峰值——**跑一次才知道**。

## 3. 工作目录约定（建议）

```
<你的工作区>/
├─ frames/        # 首帧、候选图、抽帧核对图
├─ out/           # 视频中间产物
├─ out_final/     # 成片
├─ scripts/       # 你的批处理脚本
└─ logs/          # 每个任务的日志
```

把「首帧 / 中间 / 成片 / 脚本 / 日志」分开放，后面排查会轻松很多。

---

## 4. 脚本化：别手点

整条链路都是**参数可调的批处理**，建议一开始就脚本化：

- 出图脚本：固定配方 + 换 seed 批量跑；
- 视频脚本：固定首帧 + 换参数跑；
- 后期脚本：ffmpeg 参数化。

**好处**：换 seed 抽卡、批量重跑、出问题重放，全靠脚本，不靠记忆。

> 小提醒：Windows 下脚本打印中文/日文文件名可能因编码报错，开头加一行 `sys.stdout.reconfigure(encoding="utf-8")` 就好。
